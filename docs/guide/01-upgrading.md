# Upgrading

This a placeholder for an eventual migration guide from v0.5 to v0.6.

! note: Some of these changes were first made in v0.5.3.

  Rocket v0.5.3 and the contrib library versions released alongside it made
  several of the changes below: connection lingering and most of the changes to
  templates, databases, and WebSockets. Applications that already use these
  versions are not affected by those changes. The [0.5.3 CHANGELOG] lists them
  in full.

[0.5.3 CHANGELOG]: @git/master/CHANGELOG.md#version-053-nov-18-2026

## Rust Version

Rocket v0.6 and its contrib libraries require Rust 1.95 or later.

## Contrib Versions

The contrib libraries are versioned independently of `rocket`. Use the
following versions with Rocket v0.6:

  * [`rocket_db_pools`] `0.4`
  * [`rocket_dyn_templates`] `0.4`
  * [`rocket_sync_db_pools`] `0.3`
  * [`rocket_ws`] `0.3`

For example, to update an application that uses Tera templates, make the
following changes to `Cargo.toml`:

```diff
[dependencies]
- rocket = "0.5.4"
- rocket_dyn_templates = { version = "0.3.0", features = ["tera"] }
+ rocket = "0.6.0-dev"
+ rocket_dyn_templates = { version = "0.4.0-dev", features = ["tera"] }
```

## Connection Lingering

Connections now linger for up to 10 seconds after the last response.

Previously, Rocket closed a connection immediately after the last response,
even if the client was still sending data, for instance, the rest of an upload
that exceeded a data limit. Closing a connection with unread data causes TCP to
send a reset, which can discard the response before the client reads it. Rocket
now closes connections in stages: it shuts down writes, then reads and discards
incoming data until the client closes the connection, the linger time elapses,
or the shutdown grace period ends. Upgraded connections, such as WebSocket
connections, do not linger.

As a result, connections may remain open for up to 10 seconds longer than
before. The linger time is configured via the new [`linger`] configuration
parameter. For the previous behavior, set `linger` to `0`:

```toml
[default]
linger = 0
```

[`linger`]: @api/master/rocket/struct.Config.html#structfield.linger

## Mount Points

Mount points, or bases, are now treated like route URIs: they are never
percent-decoded and are instead compared against the percent-decoded request
path. Previously, a base had to be a valid origin URI.

  * [`Rocket::mount()`], [`Rocket::register()`], [`Route::rebase()`], and
    [`Catcher::rebase()`] take a `&str` base. Pass a `String` as `&base` and
    a URI as `uri.path().as_str()`.
  * A base may contain any UTF-8 characters. A route mounted at `/häcker`
    matches requests to `/h%C3%A4cker/..`.
  * A `%` in a catcher base is no longer a percent-encoding escape. A catcher
    registered at `/a%20b` now catches errors from requests to `/a%2520b/..`,
    where routes mounted at `/a%20b` have always matched, and not `/a%20b/..`.
  * `uri!` percent-encodes static segments of a route URI and literal prefixes
    starting with `/`. These prefixes use mount-point syntax: a prefix of
    `/a%20b` generates `/a%2520b`. To use an already encoded path, pass a URI
    expression: `uri!(uri!("/a%20b"), handler)`. Absolute URI prefixes also
    preserve percent-encoding escapes.

[`Rocket::mount()`]: @api/master/rocket/struct.Rocket.html#method.mount
[`Rocket::register()`]: @api/master/rocket/struct.Rocket.html#method.register
[`Route::rebase()`]: @api/master/rocket/struct.Route.html#method.rebase
[`Catcher::rebase()`]: @api/master/rocket/struct.Catcher.html#method.rebase

## Typed URIs

URIs generated by [`uri!`] are now percent-encoded and normalized in the same
way as route URIs:

  * Static query segments are percent-encoded. A static query of `c=d+e` now
    generates `c=d%2Be`.
  * Literals that are not normalized are rejected at compile-time. Previously,
    they were normalized. For example, `uri!("/a//b")` must be written as
    `uri!("/a/b")`.
  * The URI is normalized after route arguments are substituted and any prefix
    or suffix is added. Empty dynamic segments are removed: for a route URI of
    `/<a>/<b>`, the values `""` and `"b"` generate `/b`, where they previously
    generated `//b`.

[`uri!`]: @api/master/rocket/macro.uri.html

## Mutual TLS

`x509-parser` was updated to `0.18`. The [`mtls::x509`], [`mtls::oid`], and
[`mtls::bigint`] modules reexport types from `x509-parser`, which now depends
on `der-parser` `10`, `oid-registry` `0.8`, and `asn1-rs` `0.7`. Applications
that depend on these crates directly should update them to match.

## Templates

The templating fairing is now [`Templating`]. `Template::fairing()`,
`Template::custom()`, and `Template::try_custom()` were removed:

  * Use `Templating::new()` in place of `Template::fairing()`.

  * `Template::custom()` callbacks ran _after_ templates were loaded. Callbacks
    that register helpers or configure engines should instead use
    `Templating::init()`, which runs _before_ templates are loaded:

    ```diff
    - .attach(Template::custom(|engines| {
    + .attach(Templating::init(|engines| {
          engines.handlebars.register_helper("wow", Box::new(wow_helper));
      }))
    ```

    Callbacks that add templates which use templates in `template_dir` should
    use `on_load()`. Use `try_init()` and `try_on_load()` in place of
    `try_custom()`. See [`Templating`] for details on which callback to use.

Template names now include the file type extension. A template in a file named
`index.html.tera` was previously named `index`. It is now named `index.html`.
Change the names in `Template::render()` calls and in templates, including in
inheritance, includes, and partials:

```diff
- Template::render("index", context! { .. })
+ Template::render("index.html", context! { .. })
```

```diff
- {% extends "base" %}
+ {% extends "base.html" %}
```

HTML escaping is now determined by template names alone. Tera and MiniJinja
templates with names ending in `.html`, `.htm`, `.xml`, `.xhtml`, or `.svg`,
regardless of case, are escaped. This includes templates registered in
callbacks. To render a value without escaping, mark it as safe.

Finally, `tera` was updated to `2`, `minijinja` to `3`, and `handlebars` to
`6.4`. Templates and helpers written for earlier versions may need changes.
The [0.5.3 CHANGELOG] lists these changes in detail.

[`Templating`]: @api/master/rocket_dyn_templates/struct.Templating.html

## Databases

`rocket_db_pools` updates its drivers: `sqlx` to `0.9`, `diesel` to `2.4` and
`diesel-async` to `0.10`, `mongodb` to `3`, `deadpool-postgres` to `0.14`, and
`deadpool-redis` to `0.23`. Applications that depend on a driver directly must
update the dependency to match or use the driver reexported by
`rocket_db_pools`. The [0.5.3 CHANGELOG] describes the changes required by
each driver. Additionally:

  * **SQLx pools connect lazily.**

    Previously, SQLx pools connected to the database during ignition, so an
    unreachable or misconfigured database aborted launch. Pools now connect
    when a connection is first requested, and connection errors are reported
    then. To abort launch if the database cannot be reached, acquire a
    connection in an ignite fairing:

    ```rust
    # #[macro_use] extern crate rocket;
    use rocket::fairing::AdHoc;
    use rocket_db_pools::{sqlx, Database};

    #[derive(Database)]
    #[database("sqlite_db")]
    struct Db(sqlx::SqlitePool);

    #[launch]
    fn rocket() -> _ {
        rocket::build()
            .attach(Db::init())
            .attach(AdHoc::try_on_ignite("Connect to Database", |rocket| async {
                match Db::fetch(&rocket) {
                    Some(db) if db.acquire().await.is_ok() => Ok(rocket),
                    _ => Err(rocket),
                }
            }))
    }
    ```

  * **The `extensions` configuration option is ignored.**

    `Config::extensions` was removed, and a warning is emitted if `extensions`
    is configured for `sqlx_sqlite`. To load extensions, call SQLx's
    `SqliteConnectOptions::extension()` method from a [`Database::custom()`]
    callback:

    ```rust
    # use rocket_db_pools::{sqlx, Database};
    # #[derive(Database)]
    # #[database("sqlite_db")]
    # struct Db(sqlx::SqlitePool);
    rocket::build().attach(Db::custom(|_config, (pool, connection)| {
        // SAFETY: this library is trusted for the pool's lifetime.
        let connection = unsafe { connection.extension("rot13") };
        (pool, connection)
    }))
    # ;
    ```

    The extension library _must_ be trusted whenever a connection is created.
    More generally, [`Database::custom()`] and [`Database::try_custom()`]
    configure SQLx pools and MongoDB clients during initialization.

  * **Redis commands time out after 0.5 seconds by default.**

    Commands that block by design, such as `BLPOP`, now fail if they block for
    longer than the timeout. Use the new `response_timeout` configuration
    option to set the timeout in seconds. A value of `0` disables the timeout:

    ```toml
    [default.databases.redis]
    url = "redis://localhost:6379"
    response_timeout = 0
    ```

  * **SQLite connections in `rocket_sync_db_pools` wait up to 5 seconds for
    locks.**

    The SQLite `busy_timeout` of Diesel and `rusqlite` connections was
    previously 1 second. To use a different timeout, execute
    `PRAGMA busy_timeout` in `run()`.

[`Database::custom()`]: @api/master/rocket_db_pools/trait.Database.html#method.custom
[`Database::try_custom()`]: @api/master/rocket_db_pools/trait.Database.html#method.try_custom

## WebSockets

`rocket_ws` updates `tokio-tungstenite` to `0.30`:

  * Text messages now use `Utf8Bytes`, while binary, Ping, and Pong messages
    use `Bytes`. Both types are reexported by `rocket_ws`. Use `.into()` when
    constructing messages from strings or vectors:

    ```diff
    - yield ws::Message::Ping(vec![b'h', b'i'])
    + yield ws::Message::Ping(vec![b'h', b'i'].into())
    ```

  * `Config` is now non-exhaustive. Use builder methods on `Config::default()`
    in place of struct literals:

    ```diff
    - let ws = ws.config(ws::Config {
    -     max_message_size: Some(3 << 20),
    -     ..Default::default()
    - });
    + let ws = ws.config(ws::Config::default().max_message_size(Some(3 << 20)));
    ```

  * Connections allocate an 8KiB read buffer by default. Previously, each
    connection allocated a 4KiB read buffer. A configuration passed to
    `WebSocket::config()` replaces this default, and `Config::default()` uses a
    128KiB read buffer, so applications that configure connections may use
    considerably more memory. To keep a small buffer, set its size explicitly:

    ```rust
    # use rocket_ws as ws;
    let config = ws::Config::default()
        .max_message_size(Some(3 << 20))
        .read_buffer_size(8 * 1024);
    ```

  * The `WebSocket` request guard validates `Sec-WebSocket-Key`. Requests with
    an invalid key are forwarded with `400 Bad Request`.

The [0.5.3 CHANGELOG] lists further changes to frames, close frames, and
errors.
